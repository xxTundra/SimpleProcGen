Macros

What a macro is

A macro is a named dice expression: a saved formula you can call by name from the roll bar and from |...| spans in table entries and generator templates. Macro files live in the dice-macros/ folder; each file's top level is an object with a single "items" array, and each item is a macro with a name, an optional label, and a formula.

{
  "items": [
    {
      "name": "sword",
      "label": "Sword",
      "formula": "1d20+5"
    }
  ]
}

The label is display text; where it is empty the app uses the name instead. The name is what the roll bar and the |...| spans match against.

The Macros tab

The Macros tab lists every file in dice-macros/ as its own block, showing the file's path, its macro count, and a "+ add macro" button. The tab's buttons: "+ new file" asks for a name without the .json and creates an empty file, "export all" downloads all macro files as one ttrpg-macros.json bundle, and "import…" lets you pick one or more .json files to add. With no macro files the tab shows an empty-state notice telling you to click "+ new file" or drop a JSON file anywhere on the page.

Macro rows and their fields

Each macro is a row with three text fields and a delete button, in this order: a name field (placeholder name (used for lookup)), a label field (placeholder label (display, optional)), and a formula field (placeholder formula, e.g. 1d20+5). There is no rename button and no test button — a rename is made by editing the name field, and every change to a field commits the row.

Storage and lookup order

Files are listed by path in lexicographic order, and macros within a file in the order they appear in the file; that same order is the macro order used for every lookup, so when two macros share a name the first one in that order is the one that matches.

Macro names in the roll bar

The roll bar accepts a macro name in place of an expression. The input is trimmed, and a macro name must start the whole input, matched case-insensitively, with the character after the name being the end of the input, whitespace, or one of + - * / ( — so the macro fire never matches the input fireball. When more than one name matches, the longest name wins. The matched formula is wrapped in parentheses and the rest of the input is appended after a space: with sword as 1d20+5, the input sword 1d6 rolls (1d20+5) + 1d6 and sword-1 rolls (1d20+5) - 1 — a + is inserted only when the rest starts with a digit or an opening parenthesis, and a leading operator gets a space after it. With the same macro, sword*2 rolls (1d20+5) * 2. The roll bar shows the input with an arrow to the combined expression (sword → (1d20+5)), and the combined expression is what gets rolled, in the current mode.

Why: a macro name in the roll bar stands in for the whole formula, so the saved expression is rolled without retyping it.

|macro| spans in tables and generators

In table entries and generator templates a |...| span holds either a dice expression or a macro name. The span's text is trimmed and matched by exact case-insensitive name — the first match in macro order wins — with no prefix matching and no remainder: |sword| rolls the formula as (1d20+5), while |sword 1d6| is not a macro match.

Why: a |macro| span puts a saved formula into a table entry or a template, so the formula lives in one place and every span that names it rolls it.

Failure messages

A row without a name is not saved: it needs a name first. A row whose name duplicates any other row loses to the earlier match in file order. A formula that does not parse shows the dice engine's message under a formula label. An empty input prompts for a dice expression like 2d6+3 or a macro name. A span that holds neither a macro name nor a valid dice expression fails. An empty span fails. A macro whose own formula is invalid fails.
